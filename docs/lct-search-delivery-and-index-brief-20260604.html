LCT 搜索生效计数与索引补位候选修正简报

日期：2026-06-04 分支：codex/lct-search-delivery-index-20260604 置信度：高

结论：本轮已把 v10 live E2E 复盘暴露的两个审计缺口收束到代码、测试、文档和 Skill 契约里。HTML 搜索卡片现在拆开“调用次数”和“调用生效次数”；根目录索引的 backfill_candidates 来源被固定为 terminal manifest 的 metadata.quorum.backfill_candidates。

解决的问题

  1. HTML 不再把“允许搜索”“观察到 tool call”和“搜索结果生效”混成一个口径，只展示 调用次数 和 调用生效次数。
  2. LCT manifest stage records 会持久化 WebSearch / WebFetch 的 result 交付证据、conversion error 和 effective call 计数。
  3. validate 对“调用次数大于调用生效次数”的 run 给 warning，但不把已有可用 final 判失败。
  4. <run_id>-index.md 的 backfill_candidates 只能来自 terminal manifest，缺失时写 not recorded，不得猜。

这次没有重跑 v10，也没有做新的 live council benchmark。旧 v10 artifacts 保持为复盘证据，不改写。

实现摘要

P1：搜索调用和生效拆分

  • provider.py 解析 WebSearch / WebFetch 的 tool_result event，并从复制后的 session.log 统计 Web tool output conversion failures。
  • ModelCallResult 持久化 web_tool_result_calls_count、web_tool_result_call_ids、lct_search_conversion_errors、web_tool_effective_calls_count。
  • council.py 把这些字段传播到 manifest stage records。
  • html_export.py 产出 lct_web_tool_calls、lct_web_tool_result_calls、lct_search_conversion_errors、lct_web_tool_effective_calls。
  • reviewer 反馈后，Web tool call 去重 scope 改为 per stage record，并把 persisted effective 限制到 observed calls，避免 effective > calls。

P2：索引补位候选来源固定

backfill_candidates 必须来自 terminal manifest 的 metadata.quorum.backfill_candidates。
如果 terminal manifest 没有记录该字段，写 backfill_candidates: not recorded。
不得从默认成员阵容、models --recommend --json 的 primary roster、实际有效 Stage 1 成员猜测候补池。
