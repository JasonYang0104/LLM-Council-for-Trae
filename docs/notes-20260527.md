### traecli pipe hang 最终方案

经过 4 种方案迭代：
1. `subprocess.Popen` + 文件 fd 重定向 → hang
2. `os.system` + 线程超时 → 被外部 timeout 截断
3. `signal.alarm` + `os.system` → alarm 触发但 C 层阻塞不返回
4. `subprocess.Popen(shell=True)` + shell 级重定向 → 仍然 hang

**最终方案**：`run_command` 使用 `os.system` + 临时文件重定向，移除 Python 层超时控制，由调用方整体 timeout 兜底。`os.system` 是唯一能让 traecli 正常工作的路径。代码见 `src/coco_llm_council/utils.py` 第 52-75 行。

已知限制：`os.system` 在 C 层阻塞，Python 的 `signal.alarm`、线程、`subprocess.TimeoutExpired` 等超时机制均无法中断它。`run_command` 的 `timeout` 参数对 traecli 调用变为 advisory。

## 2026-05-27 E2E 验证（历史）

### traecli 超时问题（严重）

- **现象**：8 模型 E2E run 完成后，后续 `traecli --version` 在 Python `subprocess.run(capture_output=True)` 中持续超时（30s）
- **但**：同一时间 shell 直接执行 `traecli --version` 正常返回；`os.system('traecli --version')` 也正常
- **根因**：traecli 在 stdout 是 pipe（非 tty）时走了不同的代码路径，可能尝试初始化 MCP 连接并挂起
- **修复**：`run_command` 函数增加 fallback——当 `subprocess.run` 超时后，用 `os.system` + 文件重定向重试
- **额外修复**：`os.system` 返回值在 macOS 上是 wait status，需要 `rc >> 8` 才是实际退出码
- **影响**：Q2/Q3 的 8 模型 E2E 需要此修复才能启动

### traecli 8 模型并发不稳定（已知）

- Q1（社交判断）：8 模型中 2 个 traecli result error → degraded_ok
- Q2（黑客松技术栈）：`--timeout 300` 后 8/8 全部 ok
- Q3（本地AI预测）：8 模型中 4 个超时（GPT-5.4, GLM-5.1, Doubao-Seed-2.0-Code, GPT-5.5）→ failed
- 结论：traecli 在 8 模型并发时极不稳定，部分模型（特别是 GPT-5.5, Doubao-Seed-2.0-Code）几乎必挂
- 这是 runtime 层面的问题，不是 CLC 代码问题

### traecli result error（已知）

- Doubao-Seed-2.0-Code、GPT-5.5 在 8 模型并发时频繁出现 `traecli result error`
- C2 重试逻辑已验证生效：`retried=True` + `retry_error` 正确记录
- 但重试后仍然失败，说明是 runtime 层面的问题，不是偶发错误
- 这与 project_memory 中记录的"8 模型并发时极不稳定"一致

### 规范外决定

1. **`--default-models` 只用 2 模型**：这是 `council.py` 中 `DEFAULT_MEMBERS = ["GPT-5.4", "GLM-5.1"]` 硬编码的结果。E2E 应该用 `--members` 显式指定 8 模型阵容。
2. **meta.json 重写**：C2 重试后需要重写 meta.json，因为 `_query_model_once` 在内部写 meta，但 `query_model` 包装器在返回后才设置 `retried=True`。这个修复不在原始执行方案中。
3. **模型表现摘要表格移除**：用户在看到 HTML 后决定取消"模型表现摘要"表格展示，只保留 summary cards（最高排序成员、成员模型、主席模型）。
4. **summary cards 位置调整**：从 final-answer 下方移到上方（在"阶段 3 · 主席综合"之前）。

### 权衡

1. **8 模型 vs 6 模型**：8 模型更贴近初始设计，但 traecli 并发稳定性差（Doubao-Seed-2.0-Code 22% 成功率、GPT-5.5 25%）。收敛到 6 成员阵容（移除 Doubao 系和 GPT-5.5）。
2. **重试次数**：只重试 1 次（等 10s），不指数退避。因为 traecli result error 通常是持续性的（runtime 问题），多次重试意义不大。
3. **主席选择**：优先考虑长上下文整合能力（Kimi-K2.6）而非单纯推理深度（DeepSeek-V4-Pro），因为主席需要综合多个成员的回答和排序。
