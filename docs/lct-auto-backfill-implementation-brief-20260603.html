Director Brief

LCT Auto-Backfill Implementation

LCT 已经从“默认成员失败后靠外层 Agent 整轮重跑”推进到“同一个 run 内自动补位、可降级但必须说真话”的产品形态。本轮把自动交付、质量底线、失败清理和用户可见证据绑定成同一套 runtime contract。

日期：2026-06-03 · 分支：codex/lct-auto-backfill-plan-20260603

为什么这轮值得做

旧机制的核心问题不是“失败后不能补救”，而是补救边界不清。默认模型失败时，外层 Skill 会倾向于用推荐阵容重新跑一整轮；这会浪费已经成功的 Stage 1 输出，也会让 2-member degraded result 的语义变得模糊。

这轮的判断：自动交付仍然是 LCT 的核心体验，但它不能靠模糊状态偷渡。低 quorum 可以交付，但必须在 manifest、validate、HTML、索引和最终汇报里显著可见。

产品决策

  • 默认目标仍是至少 3 个有效 Stage 1 成员，没有悄悄改成 2。
  • 成员失败后的主恢复路径变为同一个 run 内 auto-backfill：保留已成功回答，只追加候补成员，不整轮重跑。
  • low quorum 是可用降级，不是健康成功；必须标记 degraded_ok 并展示有效成员数和 backfill 尝试。
  • 主席模型失败时允许自动走备选链，但必须记录 chairman_fallback_used。
  • models --recommend --json 现在是候补池来源，而不是另起一轮的指令。
  • 补位语义分两类：Stage 1 是 member backfill，只有 Stage 1 quorum 不足时才新增候选答案；Stage 2 是 reviewer-only backfill，不新增候选答案。

关键实现

Runtime cleanup

新增 cancel_and_drain()，让 Stage 1 / Stage 2 在 quorum checkpoint、timeout 或 cancellation 后等待 pending tasks 收口。provider timeout / cancel / tool-budget kill 路径现在会留下 termination metadata。

提交：7d7fc53 fix: drain cancelled model tasks before backfill

Backfill candidate pool

候补池按显式 --backfill-members、同 vendor fallback、推荐成员、runtime safe models 的顺序生成，并过滤 primary、已尝试、主席、hard-banned、beta 和 hot queue 模型。

提交：b0d09f6 feat: add deterministic backfill candidate selection

Stage 1 auto-backfill

Stage 1 成员失败后追加新 label，例如 Response E，而不是覆盖失败成员原 slot。manifest 写入 quorum provenance，包含候补、有效成员、normal quorum 和 low quorum 状态。

提交：aba731c feat: backfill failed stage1 members in-run

Stage 2 reviewer-only backfill

Stage 2 的 subjects 和 reviewers 默认来自有效 Stage 1 成员。Stage 1 quorum 已经满足但 reviewer 失败时，CLI 只补 reviewer：候补模型使用 R4 这类 reviewer-only label，只评审既有有效 Stage 1 answers，不写 stage1/D.response.md，也不会进入 subject mapping。

manifest 明确区分 stage1_backfill_members、stage2_reviewer_backfill、review_subject_count 和 reviewer_count。

提交：9284e82 feat: backfill stage2 reviewers without adding stage1 answers

Manifest / validate / HTML 可见性

HTML summary 展示 quorum 状态、有效成员、auto-backfill 尝试、Stage 2 reviewer-only backfill 和主席备选。validate 会拒绝 low quorum 却标成 ok 的伪健康结果，也会拒绝 reviewer-only backfill 混入 subject mapping。

提交：27a53c1 feat: validate and display reviewer-only backfill provenance

Skill / README 对齐

README、canonical Skill 和 .trae Skill 删除整轮 recommended rerun 旧口径，改为同一个 run 内 auto-backfill；索引和汇报新增有效成员、quorum、member backfill、reviewer-only backfill、review subjects、reviewers 和主席备选字段。

提交：待本轮 reviewer-only 文档提交

测试证据

本轮新增覆盖 runtime cleanup、候补池过滤、Stage 1 member backfill、Stage 2 reviewer-only backfill、low quorum validate、HTML 可见性和 Skill 文档契约。最终全量验证结果以 notes.md 最后一节为准。

剩余风险

  • Stale run terminalization 未纳入本轮；validate 仍偏 read-only。
  • Forbidden tool fail-fast 的“发现后立即终止模型进程”仍是后续 PR。
  • 旧 Stage 1 retry 语义仍可能复用原 slot；auto-backfill 已保证追加、不覆盖。
  • Stage 2 reviewer-only backfill 的 prompt sidecar 仍是共享文件；batch-specific prompt path 还不是第一版范围。
