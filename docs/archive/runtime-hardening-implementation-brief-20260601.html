Runtime Hardening · 2026-06-01

LCT 运行期加固实现简报

这轮把 LCT runtime 从“能跑但容易在真实使用中误判或卡住”，推进到“有互斥、有超时、有降级、有清理、有可验证状态”。它仍不是最终成熟 runtime，但已经解决外部复盘中最容易导致误操作和假失败的主链路问题。

对象：产品负责人 / PM director 状态：实现完成 验证：94 tests + live smoke

为什么要做

外部测试证明，LCT 的入口和基本 council 流程已经成立；失败点不再是“不会启动”，而是运行期治理不足。

  • 多个 run 被重复启动，争抢同一批模型资源。
  • Stage 2 reviewer 可能挂住整个 run。
  • chairman_timeout 写进 config，却没有真实控制主席阶段。
  • Stage 3 全失败时，已有 Stage 1/2 证据却不能生成可交付降级结果。
  • 超时或取消时，traecli 子进程清理不够稳。

这轮解决了什么

P0 防自爆新增 run lease；active lock 快速失败；stale / malformed lock 可替换；创建改为原子 O_EXCL。
P0 防卡死Stage 2 增加总 timeout；超时 reviewer 写入失败记录和 sidecar；有效 review 足够时继续。
P1 说真话chairman_timeout 接入 Stage 3；新增 --stage2-timeout 和 --chairman-timeout。
P2 可收场主席和 fallback 全失败时，基于 Stage 2 排名选择最佳 Stage 1 回答作为 degraded final。
P2 可恢复provider timeout、cancel、budget kill 统一走进程树清理；POSIX 优先进程组。
状态贯通degraded_ok 贯通 manifest、CLI exit、HTML gate 和 validate。

没有解决什么

本轮没有做 P3，这是刻意收窄 scope。

  • 没有实现 global slot lease / model lease。
  • 没有做长期 telemetry 或模型稳定性画像。
  • 没有合并 provider retry 和 council retry。
  • 没有重新设计默认模型 roster。
